# Optical codec

This is the WebAssembly QR decoder used by Pastebin Worker on Windows and
Linux. It shares the repository's pinned Emscripten toolchain with the NanoRQ
codec.

The codec is a QR-only, reader-only build of `zxing-cpp` with the following
receiver-specific paths implemented in `src/optical_codec.cpp`:

- full-frame RGBA, BGRX, packed luminance and 1-bit monochrome decoding;
- metadata-directed APNG grid extraction directly into QR module matrices;
- multiple-symbol acquisition for camera QR grids.

## Requirements

- Node.js 22.22.2 or newer;
- Git 2.25 or newer;

Install and configure the shared toolchain with `pnpm setup:emscripten` from
the repository root. See [`../emscripten/README.md`](../emscripten/README.md)
for prerequisites, layout, and environment overrides.

## Build

Run the codec build from the repository root:

```sh
node codecs/optical/build.mjs
```

This writes one shared `dist/optical_codec.js` glue module, SIMD/scalar
`dist/optical_codec_simd.wasm` / `dist/optical_codec_scalar.wasm` binaries,
and the matching TypeScript declaration. The build script sparse-clones `zxing-cpp/core` and
pins it to commit `db11a782d9f8a99d9cc504360bc72e770c5e250d`; Git and network
access are therefore needed only when that revision is not already available.
Incremental builds let Ninja reconfigure CMake only when an input changed and
leave output timestamps alone when the generated bytes are identical.
The generated JavaScript banner identifies the build from the codec input hash
and build flavor, so the same inputs produce the same build identifier.

Receiver-specific zxing changes live as ordered patches under
`patches/zxing-cpp/`. The pinned checkout under `third_party/zxing-cpp` remains
pristine: the build copies `core` into its generated build directory, applies
the patches there, and compiles that disposable tree. Any local change in the
upstream checkout stops the build instead of being silently overwritten.

For faster local C++ iteration, use the isolated non-LTO build. It writes to
`build-dev` and `dist-dev`, so it cannot contaminate release artifacts:

```sh
node codecs/optical/build.mjs --dev
```

An installed compiler cache can be enabled without changing CMake files:

```sh
OPTICAL_COMPILER_WRAPPER=ccache node codecs/optical/build.mjs --dev
```

PowerShell uses `$env:OPTICAL_COMPILER_WRAPPER = "ccache"` before the build
command.

To benchmark the public full-frame decode paths, build the codec and run:

```sh
node codecs/optical/build.mjs
node --expose-gc codecs/optical/benchmark.mjs
```

The benchmark uses the SIMD binary by default; pass `--variant scalar` to
measure the fallback build.

For an alternating before/after comparison, preserve the old artifacts and
pass both directories to the benchmark:

```sh
node codecs/optical/build.mjs --output .bench/baseline
node codecs/optical/build.mjs
node --expose-gc codecs/optical/benchmark.mjs --baseline .bench/baseline --candidate dist
```

Inside the Pastebin Worker repository, run:

```sh
pnpm setup:emscripten
pnpm ensure:optical-codec
```

Run setup once to install the pinned Emscripten toolchain. The ensure command
hashes the codec sources, build configuration, ZXing revision, and local
patches, and only delegates to this subproject when the generated package is
missing or stale. It writes the three artifacts and `.build-hash` to
`frontend/optical/codec/`. The frontend build and development commands run the
same check automatically. The hosted receiver selects a variant at runtime;
the standalone exports select one at build time via `pnpm build:optical-receive`
or `pnpm build:optical-receive:scalar`.

Use `pnpm build:optical-codec` when you explicitly want to invoke the
incremental CMake/Ninja build.
